Riga di tabella (§2, §3), colonne fisse e in questo ordine:
`| tabella | righe | colonne | L | S | C | lotto sost. | decisione | motivo | prova |`
Riga di colonna (§4): `| schema.tabella.colonna | tipo | non vuote/righe | BE (file) | FE (file) | scrittori (file) | voce di piano | decisione | motivo | prova |`.

### B1.2 Regole di decisione (da scrivere in testa al file e applicare riga per riga)

### B2.1 Causa (dimostrata dal codice, riproducibile su copia)

2. Le pagine sono `lazy(import())` (`src/router.tsx:18-20`, 37 pagine; stessa funzione duplicata in `src/components/scheda/PannelloScheda.tsx:30` per 9 pagine nel pannello del diario): una scheda già aperta prima del rilascio importa un chunk che sul server non c'è più → nginx 404 → `import()` rifiuta.

Nel codice sorgente: **nessun listener** (`grep preloadError|requestIdleCallback|beforeunload|serviceWorker` in `src/`, `index.html`, `vite.config.ts`: 0).
4. **Dove finisce l'errore**: `App.tsx:12-14` mette il nostro `ErrorBoundary` *sopra* `RouterProvider`, ma React Router (7.18.4) mette un `RenderErrorBoundary` attorno alla route radice (`index === 0`) con `errorElement = defaultErrorElement` quando la route non ne dichiara uno

5. `src/router.tsx` non ha `errorElement`, né `HydrateFallback`, né `loader`: nulla dice di restare sulla pagina di prima.

`src/utils/pagineLazy.ts` (sostituisce la `pigra` di `router.tsx:18-20` e di `PannelloScheda.tsx:30`, che devono importarla):

```ts
import { lazy, type ComponentType, type LazyExoticComponent } from 'react';

export interface PaginaPigra<P extends object = object> {
  Componente: LazyExoticComponent<ComponentType<P>>;
  /** Importa il modulo (una sola volta: la promessa riuscita resta in cache; una fallita si ritenta alla chiamata dopo). */
  precarica: () => Promise<void>;
}

/** Errore di caricamento di un file dell'app: il messaggio cambia per browser (Chrome, Firefox, Safari). */
export function eErroreDiChunk(e: unknown): boolean {
  const m = e instanceof Error ? `${e.name} ${e.message}` : String(e);
  return /Failed to fetch dynamically imported module|error loading dynamically imported module|Importing a module script failed|Unable to preload CSS|ChunkLoadError/i.test(m);
}

const ATTESE_MS = [600]; // un solo ritentativo: un chunk tolto dal server non torna, e il browser può tenere in cache anche il fallimento di un import()

async function importaConRitentativo<M>(carica: () => Promise<M>): Promise<M> {
  for (let i = 0; ; i++) {
    try {
      const modulo = await carica();
      if (modulo === undefined) throw new Error('Failed to fetch dynamically imported module (modulo assente)');
      return modulo;
    } catch (e) {
      if (!eErroreDiChunk(e) || i >= ATTESE_MS.length) throw e;
      await new Promise((r) => setTimeout(r, ATTESE_MS[i]));
    }
  }
}

export function pigra<M, P extends object = object>(carica: () => Promise<M>, nome: keyof M): PaginaPigra<P> {
  let promessa: Promise<M> | null = null;
  const importa = (): Promise<M> => (promessa ??= importaConRitentativo(carica).catch((e) => { promessa = null; throw e; }));
  return {
    Componente: lazy(async () => ({ default: (await importa())[nome] as unknown as ComponentType<P> })),
    precarica: async () => { await importa(); },
  };
}

/** Importa le pagine una alla volta in tempo morto (non con connessione lenta o «risparmio dati»). */
export function precaricaInBackground(precaricamenti: ReadonlyArray<() => Promise<void>>): void {
  const conn = (navigator as Navigator & { connection?: { saveData?: boolean; effectiveType?: string } }).connection;
  if (conn?.saveData || /(^|-)2g$/.test(conn?.effectiveType ?? '')) return;
  const inTempoMorto = (f: () => void) => ('requestIdleCallback' in window ? window.requestIdleCallback(f, { timeout: 4000 }) : window.setTimeout(f, 300));
  let i = 0;
  const passo = () => {
    const prossimo = precaricamenti[i++];
    if (!prossimo) return;
    prossimo().catch(() => undefined).finally(() => inTempoMorto(passo));
  };
  inTempoMorto(passo);
}
```

import { pigra, type PaginaPigra, eErroreDiChunk } from './utils/pagineLazy';
import { useVersioneStore } from './stores/versioneStore';
import { ErrorePagina } from './components/shared/ErrorePagina';
import { SchermataAvvio } from './components/shared/SchermataAvvio'; // spinner a tutta pagina per HydrateFallback

/** Una route a pagina caricata alla prima visita: il `loader` scarica il chunk PRIMA di cambiare pagina. Se non arriva, si resta dov'eri. */
const pagina = (path: string, p: PaginaPigra): RouteObject => ({
  path,
  element: <p.Componente />,
  shouldRevalidate: () => false,
  loader: async () => {
    const prima = router.state.location; // durante un loader la posizione committata è ancora quella di prima

    catch (e) {
      if (!eErroreDiChunk(e)) throw e;
      useVersioneStore.getState().segnala('chunk');

      throw e; // caricamento iniziale: nessuna pagina di prima, lo prende ErrorePagina
    }
  },
});

  path: '/', element: <MainLayout />, HydrateFallback: SchermataAvvio, ErrorBoundary: ErrorePagina,
  children: [{
    ErrorBoundary: ErrorePagina, // dentro MainLayout: la cornice (menu, barra) resta e si può andare altrove

Note di implementazione (da verificare a vista nel browser, non provate): (a) `throw replace(url)` (esportato da `react-router` 7.18.4: `index.d.mts`, `aq as replace`) porta a una navigazione `REPLACE` verso la posizione di prima; `location.state` della pagina di prima **non si conserva** (D4). (b) Con i `loader`, al primo caricamento di un indirizzo profondo il router

const SCRIPT_CARICATO = typeof document === 'undefined' ? null
  : document.querySelector<HTMLScriptElement>('script[type="module"][src*="/assets/index-"]')?.getAttribute('src') ?? null;

export async function esisteNuovaVersione(): Promise<boolean> {

}

import { useEffect } from 'react';
const sporche = new Map<string, string>(); // chiave → etichetta mostrata all'utente
const guardia = (e: BeforeUnloadEvent) => { if (sporche.size) { e.preventDefault(); e.returnValue = ''; } };

### B10.1 Il registro delle fonti tolte: `server/db/fontiTolte.ts` (nuovo, perno del blocco)

Un solo elenco, aggiornato **da ogni migrazione che toglie una tabella o una colonna** (B8, B9, B12, B15 e le eliminazioni di partite), usato da import, cestino ed export. Così non servono né liste sparse né rilevamenti euristici per sapere «che cosa è stato tolto e dove vive adesso».

```ts
export interface FonteTolta {
  schema: 'main' | 'utente';
  tabella: string;
  colonna: string | null;          // null = tabella intera
  tolta: string;                   // «L11 · migrazione <id>»
  sostituitaDa: string;            // in italiano, per l'utente: «le planimetrie dell'Area (L2)»
}
export const FONTI_TOLTE: readonly FonteTolta[] = [
  // si riempie con ogni migrazione di eliminazione; es. { schema: 'main', tabella: 'marcatore_luogo', colonna: null, tolta: 'L11 · 17x', sostituitaDa: 'i pin dei luoghi (L5)' }
];
export const tabellaTolta = (schema: string, tabella: string): FonteTolta | undefined => FONTI_TOLTE.find((f) => f.schema === schema && f.tabella === tabella && f.colonna === null);
export const colonnaTolta = (schema: string, tabella: string, colonna: string): FonteTolta | undefined => FONTI_TOLTE.find((f) => f.schema === schema && f.tabella === tabella && f.colonna === colonna);
/** Un registro del cestino (o una riga) è compatibile con lo schema di oggi se ogni colonna di oggi c'è nella riga e ogni colonna in più è dichiarata tolta. */
export function colonneCompatibili(schema: string, tabella: string, chiaviRiga: readonly string[], colonneOggi: readonly string[]): boolean {
  return colonneOggi.every((c) => chiaviRiga.includes(c)) && chiaviRiga.every((k) => colonneOggi.includes(k) || !!colonnaTolta(schema, tabella, k));
}
```
Regola da scrivere in testa al file: **una voce non si toglie mai** (serve ai cestini e ai backup vecchi), anche quando la migrazione che l'ha tolta è lontana; le **etichette** delle tabelle tolte in `ETICHETTE` (`cestinoService.ts:103-143`: `marcatore_mappa`, `marcatore_luogo`, `pianta_area`, `guida_mappa`, `mappa_entita`…) **restano**, perché danno il nome leggibile alle righe saltate: **B19 non deve ripulirle**.
Dipendenza: B8, B9, B12 e B15 aggiungono qui le loro voci nella stessa migrazione; B10 va quindi **prima** di loro.

### B10.2 Riepilogo di cosa è stato scartato (R11-05/3)

**Che cosa si confronta e quando.** Prima di installare il file: la struttura (tabelle e colonne) del pacchetto in ingresso contro quella dell'istanza **viva** (`getDb()`, già migrata al codice corrente: è lo schema di arrivo). Non serve confrontare «prima e dopo le migrazioni»: il file in ingresso si legge in sola lettura e lo schema di arrivo è già in mano. L'anteprima mostra il riepilogo prima della conferma, l'esito lo ripete.

**Perché non guardare «dopo»**: `installaDatabase(file, …, 'sposta')` sposta il file in ingresso; dopo `riapriIstanza()` i dati scartati sono nella sola copia di sicurezza. Il confronto con lo schema vivo dà lo stesso risultato **prima**, sullo stesso file, senza toccare le migrazioni.

**Due livelli**: (a) **dichiarate**: voci di `FONTI_TOLTE` presenti nel backup, con `sostituitaDa` (spiegano «dove vive ora»); (b) **non dichiarate**: tabelle o colonne del backup che lo schema vivo non ha e che nessuna voce spiega (probabili rinomine o strutture storiche); si mostrano separate, con la scritta «non spiegate». Prova su dati reali: il confronto fra `pacchetto/gioco.db` (v93) e la copia a 146 dà **una** tabella (`seed_meta`, 4 righe) e una colonna (`dungeon_area.timbri_totale`, tutta a 0), cioè pochi falsi positivi.
Regola di «valore informativo» per le colonne: una riga conta se il valore non è NULL né uno di `''`, `'[]'`, `'{}'`, `'0'`, `'null'` (D10); se nessuna riga conta, la colonna non si segnala.

function strutturaDi(db: Database.Database): Map<string, string[]> {

/** Le strutture del pacchetto che l'istanza (schema di arrivo) non ha. Sola lettura sul pacchetto; esportata per la prova senza test. */
export function scartiDelPacchetto(pacchetto: Database.Database, istanza: Database.Database): ScartoPacchettoDto[] {
  const dentro = strutturaDi(pacchetto), qui = strutturaDi(istanza), out: ScartoPacchettoDto[] = [];
  for (const [tabella, colonne] of dentro) {
    const tolta = tabellaTolta('main', tabella);
    if (!qui.has(tabella)) {
      const righe = (pacchetto.prepare(`SELECT COUNT(*) AS n FROM main."${tabella}"`).get() as { n: number }).n;
      if (righe > 0) out.push({ tipo: 'tabella', tabella, etichetta: etichettaTabella(tabella), colonna: null, righe, sostituitaDa: tolta?.sostituitaDa ?? null, spiegata: !!tolta });
      continue;
    }
    for (const colonna of colonne.filter((c) => !qui.get(tabella)!.includes(c))) {
      if (colonna === 'contenuto') continue; // BLOB: non si scandisce
      const righe = (pacchetto.prepare(`SELECT COUNT(*) AS n FROM main."${tabella}" WHERE ${INFORMATIVO(colonna)}`).get() as { n: number }).n;
      const dich = colonnaTolta('main', tabella, colonna);
      if (righe > 0) out.push({ tipo: 'colonna', tabella, etichetta: etichettaTabella(tabella), colonna, righe, sostituitaDa: dich?.sostituitaDa ?? null, spiegata: !!dich });
    }
  }
  return out.sort((a, b) => Number(b.spiegata) - Number(a.spiegata) || a.tabella.localeCompare(b.tabella));
}

### B10.5 Che cosa vale «export senza le tabelle tolte»

L'export (`GET` del pacchetto → `copiaDatabase('gioco')`, e lo ZIP dell'istanza → `copiaIstanza`) è la copia dell'intero schema vivo (`db.backup`): vale «non contiene le tabelle e le colonne tolte» **se e solo se** la migrazione le ha davvero eliminate dal file. Non serve codice di filtro. Provare con il controllo di §B10.7. Due precisazioni da scrivere nei documenti: (1) le pagine libere non vengono azzerate: i byte delle tabelle tolte possono restare fisicamente nel file fino a un `VACUUM` (le tabelle tolte da L11 sono piccole; `VACUUM` su 413 MB richiede il doppio dello spazio, non lo propongo); (2) `pacchetto/gioco.db` in git è a schema 93: dopo i drop si rigenera con `npm run pacchetto` (modifica un binario versionato: lo fa chi ha l'incarico, non B10).

## Limiti di questa analisi

- Non ho aperto `data/` del worktree né nessun dato dell'istanza dell'utente; ho usato solo `sim-142b` e `pacchetto/gioco.db` (schema 93) in sola lettura.
